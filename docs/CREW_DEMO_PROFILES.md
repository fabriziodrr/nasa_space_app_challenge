# Crew profiles for the demo

In Houston → Crew Data you can choose one of five fictional astronauts. The profiles are defined in `server/examples/crew_profiles.ts`: names, roles, identifiers, self-assessments, vigilance tests, and sleep observations are invented. They do not represent people or NASA recordings. Mood and quality scales are examples, not validated psychometric tools.

In the Sleep recovery panel, if the selected profile's sample is not found in the analysis, it is automatically imported into the Python backend with a unique `subject_id`. The **Load sensor demo** button also allows you to retry manually. The first profile uses the existing `sleep-demo-14d` sample, which has not been modified. The other profiles have separate observations. If the ID has already been imported, the measurement is not overwritten. Cognitive state and Vigilance test instead show static data from the respective profiles and do not record them in the backend. Changing profile does not change the agent session or the vision.

The demo agent uses a server mapping to associate `astro-1` with `sleep-demo-14d` and the other four IDs with the corresponding Python subjects. Select the same profile in chat, Crew Data, and schedule. The token `AGENT_DEMO_TOKEN` identifies Alex; `AGENT_CREW_02_TOKEN` through `AGENT_CREW_05_TOKEN` identify the other astronauts. Tokens must be distinct, private, and at least 16 characters long. Restart Next after configuring them; Terra sees only profiles with configured credentials. Vision measurements selected from chat, check-ins, reports, and schedules are tied to the agent session identity.

The mapping is a convention for fictional profiles: recent synthetic readings linked by the server are marked `demo_mapped` and can motivate proposals together with shared statements. Missing, truncated, out-of-range, or unknown-association readings are not usable as evidence for the schedule. The sample generated by Sleep recovery uses the current day and simulated data; the vision measurement retains its own origin. The Vision report section of Crew Data and the Python integrated context endpoint continue to use the fixed subject `sleep-demo-14d`; they should not be interpreted as data from the selected profile. Real identities and authorizations will be required before handling real health data.

The categories are inspired by research documented by NASA: the [Spaceflight Standard Measures](https://ntrs.nasa.gov/api/citations/20230014025/downloads/SSM%20IWS24%20Spaceflight%20Standard%20Measures.pdf) study includes sleep, cognition, and other measures; the [NASA Life Sciences Portal](https://www.nasa.gov/hrp/nlsp/) collects de-identified human research data, with procedures for requests. The [Open Science Data Repository](https://science.nasa.gov/reference/osdr-faq/) includes some public processed data and controlled-access data. No NASA dataset has been imported or linked to the profiles here.
